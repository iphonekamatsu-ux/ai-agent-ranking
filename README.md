# toolgit — AI エージェント関連 GitHub リポジトリ ランキング取得ツール

GitHub 上の AI エージェント関連リポジトリを star 数で集計し、Markdown のランキング表を作ります。
定期的に実行することで「どれだけ star が伸びたか」も分かるようになります。

外部ライブラリは一切使いません（Node.js 18 以上のみ）。

---

## 使い方（いちばん簡単な方法）

**`run.bat` をダブルクリックするだけです。**

1〜2分待つと、`reports\latest.md` にランキングができます。

コマンドで実行したい場合:

```
npm start
```

---

## 取得している情報源

| 情報源 | 内容 | 費用 | 認証 |
|---|---|---|---|
| **GitHub** | AI エージェント関連リポジトリの star ランキング | 無料 | 不要 |
| **Hacker News** | AI 関連で話題になった記事 | 無料 | 不要 |
| **Hugging Face** | トレンドのモデルと注目論文 | 無料 | 不要 |
| **arXiv** | cs.AI / cs.MA / cs.CL の新着論文 | 無料 | 不要 |
| **Zenn** | 日本語の AI 記事 | 無料 | 不要 |
| **Qiita** | 日本語の AI 記事 | 無料 | 不要 |
| **Reddit** | r/LocalLLaMA など AI 系の人気投稿 | 無料 | **要登録**（下記参照） |

Reddit 以外は準備なしで動きます。Reddit は認証情報が無ければ自動でスキップされ、
他の情報源には影響しません。

## できること

レポートは4部構成です。

### 1. 累計 star ランキング

star 数が多い順のランキング。**初回から出ます。**

### 2. 新顔ランキング（作成日ベース）

「直近1週間 / 1ヶ月 / 3ヶ月 / 6ヶ月 / 1年 に**新しく作られた**リポジトリ」のランキング。
**これも初回から出ます。**

### 3. 伸びランキング（star 増加ベース）

「直近1週間 / 1ヶ月 / … で **star がどれだけ増えたか**」のランキング。

⚠️ **これだけは時間が必要です。** GitHub は「30日前の star 数」を教えてくれないため、
このツールが自分で記録を貯めて差分を計算します。

| 期間 | 出せるようになる時期 |
|---|---|
| 直近1週間 | 実行開始から約6日後 |
| 直近1ヶ月 | 約24日後 |
| 直近3ヶ月 | 約72日後 |
| 直近1年 | 約292日後 |

まだ貯まっていない期間は「⏳ データ蓄積中 — あと約N日」と表示され、
条件が整えば**自動的に**表示に切り替わります。**早く始めるほど早く使えるようになります。**

### 4. GitHub 以外の情報源

情報源ごとに3つに分けて表示します。**同じ記事が毎週並ぶのを防ぐため**の作りです。

| 表示 | 内容 |
|---|---|
| 🆕 新着 | 前回の記録に無かったものだけ |
| 📈 前回から伸びたもの | スコアが上がったもの（+120pt など） |
| 総合トップ | 期間内の上位。既出には 🔁 が付きます |

実測では、7日分と14日分で**91%の記事が重複**していました。この3分割により、
毎週見ても「今週何が新しいのか」がひと目で分かります。

## ファイル構成

```
toolgit/
├─ run.bat                 ← ダブルクリックで実行
├─ config.json             ← 設定（対象トピック・除外リストなど）
├─ src/
│   ├─ index.js            取得 → レポート生成をまとめて実行
│   ├─ fetch.js            GitHub から取得してスナップショット保存
│   ├─ feeds.js            GitHub 以外の情報源をまとめて取得
│   ├─ sources/            情報源ごとの取得処理
│   │   ├─ hackernews.js   ├─ huggingface.js  ├─ arxiv.js
│   │   ├─ zenn.js         ├─ qiita.js        └─ reddit.js
│   ├─ report.js           スナップショットからレポート生成
│   └─ lib.js              共通処理
├─ snapshots/              取得した生データ（YYYY-MM-DD.json）※消さないでください
│                          ここが「伸びランキング」の元データです
├─ reports/
│   ├─ latest.md           最新のレポート ← これを読む
│   └─ YYYY-MM-DD.md       日付ごとの保存版
└─ .github/workflows/
    └─ weekly.yml          GitHub 上で毎週自動実行するための設定
```

## 設定の変え方（config.json）

### 対象を変える

```json
"topics": [
  { "topic": "ai-agent", "minStars": 500 }
]
```

`topic` は GitHub のトピック名、`minStars` はその star 数以上だけ拾う下限です。
行を足せば対象が増え、`minStars` を下げると小さいリポジトリも入ります。

### 関係ないリポジトリを消す

トピックは作者が自由に付けられるため、無関係なリポジトリが混じることがあります。
その場合は除外リストに追記してください。

```json
"exclude": {
  "repos": ["Snailclimb/JavaGuide"]
}
```

追記したら **`npm run report` を実行するだけ**で反映されます（再取得は不要です）。

### 表示件数を変える

```json
"report": { "topN": 30 }
```

## GitHub 上で自動実行する場合

このフォルダを GitHub のリポジトリに置くと、`.github/workflows/weekly.yml` により
**毎週月曜 9:00（日本時間）に自動実行**され、結果が自動でコミットされます。

- PC の電源が入っていなくても動きます
- 公開リポジトリなら **完全無料**、非公開でも無料枠（月2,000分）で十分です
- **トークンの設定は不要です**（GitHub が実行時に自動で用意します）

手動で動かしたいときは、GitHub の **Actions** タブ →「週次ランキング取得」→ **Run workflow** です。

> 公開リポジトリの場合、60日間まったく更新がないと GitHub が定期実行を自動停止します。
> このツールは実行のたびに結果をコミットするため、動いている限り止まりません。

## Reddit を有効にする（任意・無料）

Reddit だけは認証なしのアクセスを拒否します（実測で 403）。使いたい場合は
**無料のアプリ登録が1回だけ**必要です。クレジットカードは不要です。

### 手順

1. https://www.reddit.com/prefs/apps を開く（Reddit アカウントが必要）
2. 一番下の **「create another app...」** ボタンを押す
3. 次のように入力する

   | 項目 | 入力内容 |
   |---|---|
   | name | `ai-agent-ranking`（何でもよい） |
   | 種別 | **script** を選択 |
   | redirect uri | `http://localhost:8080`（使わないが必須項目） |

4. **create app** を押す
5. 表示される2つの値を控える
   - アプリ名の下の短い文字列 → **client ID**
   - `secret` の欄 → **client secret**

### GitHub Actions で使う場合

リポジトリの **Settings → Secrets and variables → Actions → New repository secret** で
次の2つを登録します。ワークフロー側は設定済みです。

- `REDDIT_CLIENT_ID`
- `REDDIT_CLIENT_SECRET`

### 手元の PC で使う場合

PowerShell で環境変数を設定してから実行します。

```
$env:REDDIT_CLIENT_ID = "控えた client ID"
$env:REDDIT_CLIENT_SECRET = "控えた client secret"
npm start
```

## 社内ネットワークでの注意

社内ネットワークが通信を検査している環境では、GitHub 以外のサイトで
証明書エラー（`UNABLE_TO_GET_ISSUER_CERT_LOCALLY`）が出ることがあります。

`run.bat` は対策済みですが、コマンドで実行する場合は次を先に設定してください。

```
$env:NODE_OPTIONS = "--use-system-ca"
```

GitHub Actions（クラウド実行）では発生しません。

## トークンについて（任意）

トークンなしでも動きます。設定すると取得が速くなります（API 制限が 10回/分 → 30回/分）。

PowerShell で環境変数を設定してから実行してください。

```
$env:GITHUB_TOKEN = "あなたのトークン"
npm start
```

GitHub Actions で動かす場合は設定不要です。
